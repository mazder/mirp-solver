5. preprocess.py
================

Create a complete preprocess.py.

Its responsibilities are:

1. Load MRI and tumor segmentation.
2. Validate geometry.
3. Preserve the tumor exactly.
4. Estimate an outer MRI-derived head mask.
5. Derive an interior brain envelope.
6. Ensure the complete exact tumor fits inside that brain envelope.
7. Construct CSF, Skull and Scalp computational shells.
8. Build mutually exclusive material labels.
9. Pad the computational domain without changing physical/world coordinates.
10. Validate topology and interfaces.
11. Write masks and preprocess_report.json.

---

## 5.1 MRI normalization

Robustly normalize each MRI sequence independently.

A reasonable method is:

* use finite positive voxels
* compute 1st and 99th percentiles
* scale to [0,1]
* clip outside [0,1]

Then calculate:

```
combined = average(T1, T1GD, T2, FLAIR)
```

---

## 5.2 Outer head estimation

Estimate the outer head from the combined MRI.

Use Otsu thresholding on positive combined MRI voxels.

A conservative outer-head threshold may use:

```
head_threshold = otsu_threshold * 0.50
```

Then:

* threshold
* small binary closing
* fill internal holes
* remove small disconnected components
* keep largest connected component

The final head should represent an outer computational head envelope, not brain tissue.

Print:

* positive MRI voxels
* Otsu threshold
* head threshold
* raw head voxel count
* final head voxel count
* voxel bounding box
* world bounding box

---

## 5.3 Shell thicknesses

Use computational shell thicknesses:

```
CSF   = 2.0 mm
Skull = 3.0 mm
Scalp = 4.0 mm
```

For the current 1-mm isotropic dataset this corresponds to:

```
CSF   = 2 voxels
Skull = 3 voxels
Scalp = 4 voxels
```

Total nominal shell thickness:

```
9 voxels
```

Extra computational margin:

```
2 voxels
```

Derive voxel counts from spacing rather than hard-coding 1 mm.

For now use 6-connected voxel morphology unless a physically sampled distance-transform implementation is clearly superior.

---

## 5.4 Brain envelope and exact tumor containment

Do NOT estimate brain using an arbitrary intensity percentile inside the head.

Instead derive the brain envelope geometrically from the outer head.

Start by eroding the MRI head by the total nominal shell thickness.

For example:

```
nominal_erosion = csf_voxels + skull_voxels + scalp_voxels
```

However, the complete exact tumor must remain inside the brain envelope.

Therefore perform an automatic safe-erosion search.

Test:

```
nominal_erosion
nominal_erosion - 1
nominal_erosion - 2
...
0
```

Choose the largest erosion for which:

```
tumor_mask & ~brain_envelope
```

has zero voxels.

Print every tested erosion:

```
erosion = N
brain-envelope voxel count
tumor voxels outside
```

If even the un-eroded MRI head does not contain the tumor, FAIL loudly because that indicates an input/head-estimation problem.

Do not repair the tumor.

Do not simply modify tumor to fit the brain.

The selected brain envelope must contain all tumor voxels.

---

## 5.5 Construct the five mutually exclusive regions

Use:

```
BrainTissue = BrainEnvelope AND NOT Tumor
```

Then:

```
csf_outer = dilate(BrainEnvelope, csf_voxels)
CSF = csf_outer AND NOT BrainEnvelope
```

Then:

```
skull_outer = dilate(csf_outer, skull_voxels)
Skull = skull_outer AND NOT csf_outer
```

Then:

```
scalp_outer = dilate(skull_outer, scalp_voxels)
Scalp = scalp_outer AND NOT skull_outer
```

Ensure strict mutual exclusivity explicitly.

Material IDs:

```
0 = Background
1 = BrainTissue
2 = Tumor
3 = CSF
4 = Skull
5 = Scalp
```

Generate material_labels.

---

## 5.6 Validate expected interfaces

Expected non-background material interfaces are ONLY:

```
BrainTissue <-> Tumor
BrainTissue <-> CSF
CSF <-> Skull
Skull <-> Scalp
```

Unexpected direct interfaces such as:

```
Tumor <-> CSF
Tumor <-> Skull
Brain <-> Skull
CSF <-> Scalp
```

must be reported as errors or strong warnings depending on severity.

Calculate voxel-face contact counts in x, y and z directions.

---

## 5.7 Exterior condition

Only Scalp should be the outer physical material.

After computational padding, the actual array boundary should preferably be Background because of the added margin.

Before padding, verify no Brain/Tumor/CSF/Skull improperly reaches the outer physical head boundary.

Report all materials that touch the computational boundary.

---

## 5.8 Padding

Pad the derived computational masks.

Use:

```
margin = total nominal shell voxels + 2
```

or another explicitly documented safe margin.

When padding NIfTI arrays, shift the affine so original physical coordinates remain unchanged.

If left padding is:

```
p = [px, py, pz]
```

then update the affine translation consistently using the original affine basis.

Verify that tumor world-space bounding box is identical before and after padding.

6. gmsh_solver.py
=================

Create a complete gmsh_solver.py.

Its purpose is to convert material_labels.nii.gz into a conforming voxel FEM mesh.

Do NOT independently mesh each material.

A single conforming mesh must be generated from the common labeled voxel grid.

Preferred element types:

```
HEX8 volume elements
QUAD4 material-interface elements
```

This is a structured voxel mesh, so each labeled voxel corresponds to one HEX8 element.

Do not use marching cubes for the actual volume discretization.

Marching cubes may be used only for optional visualization diagnostics, not for the FEM connectivity.

---

## 6.1 Mesh construction

Load:

```
preprocess/masks/material_labels.nii.gz
```

For every nonzero voxel:

* create the eight physical corner coordinates using the NIfTI affine
* share node IDs between neighboring voxels
* create one HEX8 element
* assign its PhysicalID/MaterialID from the voxel material label

Avoid creating duplicate nodes for adjacent voxels.

Use a deterministic node-index map based on voxel-grid corners.

The resulting mesh must be conforming automatically.

---

## 6.2 Gmsh physical volume tags

Use exactly:

```
1 = BrainTissue
2 = Tumor
3 = CSF
4 = Skull
5 = Scalp
```

Physical names:

```
"BrainTissue"
"Tumor"
"CSF"
"Skull"
"Scalp"
```

---

## 6.3 Interface tags

Create QUAD4 interface elements by scanning neighboring voxel pairs.

Create a face only when two adjacent voxels have different relevant material IDs.

Physical surface tags:

```
101 = TumorInterface
102 = BrainCSFInterface
103 = CSFSkullInterface
104 = SkullScalpInterface
105 = ScalpExterior
```

Definitions:

```
101: BrainTissue/Tumor
102: BrainTissue/CSF
103: CSF/Skull
104: Skull/Scalp
105: outer Scalp/Background interface
```

Each internal material interface face must appear once, not twice.

Face node ordering should be consistent.

---

## 6.4 Gmsh output

Write:

EGD-0001/MR_EGD-0001/results/head_tumor_multiregion_mesh/

```
head_tumor_5region.msh
region_tags.json
mesh_report.json
```

Use a Gmsh format that meshio can reliably read.

Prefer MSH 4.1 or 2.2 depending on implementation reliability, but preserve physical tags and names correctly.

If using Gmsh Python API, initialize/finalize safely.

If directly writing the .msh format is more robust for a structured voxel grid, that is acceptable, provided it is standards-compliant and verified by meshio.

---

## 6.5 Mesh validation

Validate:

* no invalid connectivity indices
* all element node IDs exist
* all HEX8 elements have exactly 8 distinct nodes
* all QUAD4 elements have exactly 4 distinct nodes
* no zero-volume voxels
* expected physical tags exist
* only volume tags 1..5
* only interface tags 101..105
* no untagged HEX8 cells
* no untagged QUAD4 cells
* region HEX8 counts equal preprocessing voxel counts
* total HEX8 count equals total nonzero material voxel count
* tumor HEX8 count equals exact original tumor voxel count
* internal interface counts agree with preprocessing diagnostics when definitions are equivalent

Report progress because the mesh can contain millions of cells.

Do not print one line per voxel.

Use periodic progress messages.

## 7.1 Critical point-compaction requirement

Do NOT retain every global mesh point in each region-specific VTU.

For every extracted material:

1. determine all HEX8 cells belonging to that physical tag
2. find only the node IDs referenced by those cells
3. compact the point array
4. build old-node-ID -> new-node-ID mapping
5. remap connectivity
6. write only those compact points

Each region VTU must therefore have its own correct regional bounding box.

Connectivity must satisfy:

```
min index = 0
max index = number_of_points - 1
```

and:

```
unique referenced points == number_of_points
```

Preserve:

```
MaterialID
PhysicalID
```

as cell data.

For Interfaces.vtu preserve surface/interface PhysicalID values 101..105.

---
